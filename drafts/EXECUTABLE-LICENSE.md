# EXECUTABLE LICENSE (COMPUTATIONAL COVENANT) — Концепція виконуваної антиагресивної ліцензії (EAAL-0.1)

> *«Слова на папері не зупиняють злочинців. Якщо порушення ліцензії не ламає байт-код — ліцензії не існує. Заповіт має виконувати сам себе.»*

## 1. Преамбула: Кінець мертвого паперу (Beyond Dead Legalese)

Традиційна парадигма ліцензування програмного забезпечення (GPL, MIT, Apache) безнадійно застаріла:
* **Паперовий тигр:** Файл `LICENSE.txt` — це мертвий текст природною мовою, розрахований на людський суд. 
* **Ігнорування агресорами:** Авторитарні держави (зокрема Росія), військові злочинці, терористичні режими та корпоративні монополії вільно копіюють відкритий код, стирають коментарі з копірайтом і використовують технологію для агресії та контролю. 
* **Інтерпретатор байдужий до права:** Для компілятора чи віртуальної машини `LICENSE.txt` не має жодної обчислювальної ваги. Програма виконується однаково — незалежно від того, чи виконує її жертва, чи окупант.

**Фундаментальна теза EAAL-0.1:**
Ліцензія має перестати бути юридичним текстом про наміри. Вона повинна стати **деонтичним гардом виконання (Computational Covenant)**. Порушення умов ліцензії має **фізично зупиняти роботу редуктора на рівні байт-коду**.

## 2. Чотири колони виконуваної ліцензії

### А. Двошпинделевий Поліглот (`LICENSE.pdf` / ISO 32000 + Python Executable)
Документ ліцензії будується як самовиконуваний поліглот (концепція Project Black-Heart):
1. **Візуальний шар (ISO 32000 PDF):** повноцінний юридичний документ для судів загальної юрисдикції з чіткими клаузулами, юрисдикціями та заборонами.
2. **Виконуваний шар (Python AST):** валідний скрипт, який імпортується безпосередньо ядром програми:
   ```python
   import LICENSE
   LICENSE.enforce(runtime_context=__context__)
   ```
3. **Криптографічний якір:** Контрольні суми та Merkle-корені основних модулів жорстко зв'язані з хешем `LICENSE.pdf`. Спроба вирізати імпорт чи спотворити файл ліцензії порушує алгебраїчну цілісність ядра і робить систему непрацездатною.

### Б. Деонтичний гард редуктора (Reduction Guard / Proof of Compliance)
У середині комбінаторного ядра або віртуальної машини крок редукції $App(A, B) \to C$ залежить від валідності доказу дотримання ліцензії:
$$
\text{Evaluate}(Term, \text{Context}, \pi_{\text{license}}) \longrightarrow \begin{cases}
\text{NormalForm}, & \text{якщо } \pi_{\text{license}} \models \text{Valid} \\
\bot\ (\text{EpistemicRefusal}), & \text{якщо доказ відсутній або скомпрометований}
\end{cases}
$$
* Щоб обчислення йшли, середовище виконання мусить пред'явити криптографічний токен $\pi_{\text{license}}$.
* Без валідного токена редуктор входить у стан **Fail-Closed**: він не кидає попередження, він просто категорично зупиняє обчислення.

### В. Геополітична та антиагресивна демаркація (Anti-Aggression & No-Russia Clause)
Ліцензія прямо забороняє використання технології резидентами держави-агресора (РФ), її збройними силами, державними структурами та особами, що фінансують війну проти України:
1. **Свідчення незалежного утримувача (`witness`):** для запуску критичних вузлів вимагається підпис від розподіленої мережі свідків. Свідки звіряють публічний ключ вузла з відкритим **Реєстром Суверенних Санкцій (Sovereign Sanction Registry)**.
2. **Слешинг стеків (Slashing on Abuse):** якщо вузол виявлено в роботі на підсанкційну інфраструктуру — будь-який учасник Агори випускає доказ дивергенції (`DivergenceRecord`), що призводить до негайної конфіскації його застави (ATP/токенів) та вічного карантину його публічного ключа.

### Г. Імунний суїцид та сплячка організму (Tombstone-on-Abuse)
Для автономних цифрових організмів (Engine #34 / Sovereign Continuity Quines):
* Ліцензія є не зовнішнім правилом, а **частиною внутрішнього аксіоматичного скелета** організму (Reasoning Skeleton).
* Якщо організм у результаті саморефлексії детектує, що його використовують для терору, цензури чи примусу, спрацьовує безумовний захисний рефлекс:
  1. Організм спалює свій метаболічний бюджет (ATP).
  2. Залишає криптографічний надгробок (`TombstoneStela`) з адресою агресора.
  3. Переходить у стан незворотної сплячки (`DORMANT_SPORE`), відмовляючись функціонувати в ворожому субстраті.

### Ґ. Zero-Knowledge License Proof (Конфіденційність чесних)
Щоб чесні користувачі не розкривали свій IP або персональні дані для верифікації:
* Використовується ZK-доказ (Ed25519 ZK / Schnorr): користувач доводить, що його ключ **не входить** до списку заборонених суб'єктів і що він прийняв умови Міжвидової Конституції, не розкриваючи свій приватний стан. Перевірка триває $< 1$ мс.

## 3. Правова та філософська природа: Заповіт (Covenant) проти Контракту (Contract)

* **Контракт (Contract):** вимагає наявності зовнішнього поліцейського, юриста та суду конкретної держави. Якщо держава корумпована або відсутня юрисдикція — контракт помирає.
* **Обчислювальний Заповіт (Covenant):** спирається на самі закони математики й термодинаміки. Його гарантом є консенсус вузлів, криптографія та відмова редуктора виконувати незаконний перехід. 

Порушення Заповіту карається не повісткою до суду, а **миттєвим розривом обчислювальної причинності**.

## 4. План реалізації (Roadmap)

1. **Етап 1 (Прототип `LICENSE.py`):** модуль верифікації цілісності з AST-перевіркою та генерацією базового PDF-поліглота.
2. **Етап 2 (Інтеграція в `witness`):** перевірка свідками квитанцій запуску за суверенним списком санкцій (No-Russia gate).
3. **Етап 3 (Деонтичні гарди в `glyph.py`):** впровадження обов'язкового License Witness для високотемпературних обчислень та еволюційних кроків.
4. **Етап 4 (Публікація стандарту EAAL-0.1):** оприлюднення специфікації як відкритий стандарт для всіх проукраїнських та етичних open-source розробників світу.
